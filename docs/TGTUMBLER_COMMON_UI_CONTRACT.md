# TGtumbler 共通UI・ウィザード契約｜2026-11-05 Master確定

適用：3掲示板でBotを使用するすべてのメニュー選択・テキスト/画像/動画入力・作成・編集・検索・投稿の画面操作。これは既決の共通仕様であり、新たに提案する機能ではない。未決定の各子セクションの内容は勝手に確定しない。

## 1. ボタン・遷移
- Bot DM内の選択・前へ/次へ・戻る・編集・保存・取消・公開確認はTelegram InlineKeyboard callback_query。ボタンラベル/内部キーを利用者のテキスト発言としてチャットへ投稿しない。本文内に見せかけのボタンを描かず、実際の操作は本文直下のボタン。
- セクション遷移は基本的に同じBotメッセージIDを編集し、前画面をチャット内に積み重ねない。画面本文とInlineKeyboardを一緒に更新。入力欄に自由入力が必要な場合以外、無意味なBot replyを増やさない。
- 通常のテキスト/写真/動画等を本人DMに送信させた場合、処理の成功/失敗にかかわらず送信メッセージ削除を試行し、入力エラーは同一画面で再入力案内する。API拒否時には削除済みと報告せず手動削除案内。データベース下書きへの必要な保存とは区別。
- 古いボタン操作は利用者・所属チャット・revision・現在stepなどで拒否。二重送信や他人操作を許さない。入力失敗時には正常に選択済みの値を消さず、部分編集と戻り先を保護。
- 取消や戻るは当該画面で確定した戻り先へ誘導し、保存済み原本・他セクション・公開済み投稿を誤削除しない。進行途中の別画面操作では下書き保持・復帰を優先し、無用な全再入力はさせない。
- ボタンは確定された横並びの行構成、順序、表示文言を維持。空欄やダミーの穴埋め禁止。全ボタンを無条件で縦1列にしない。長文プレビューと操作ボタンを分離し、カテゴリーの必要な選択肢だけ表示。
- Telegramにより前画面の編集が拒否された場合だけ代替画面を作り旧画面の削除を試行。Telegramの制限上、消去100%保証はしない。公開投稿、常設案内、公開用メッセージ、送信台帳は画面掃除の対象外。
- 公開グループのURL/deep linkボタンはBot DMのcallbackとは異なる。押下元のグループ・Topicを検証済みトークンのDB対応表から復元。Telegramが/startを表示する可能性を否定しない。
- Android/iOS/iPadOS/Windows/macOSでTelegram標準機能を採用。CIと端末実機テストは別評価で、実機未検証をPASSと報告しない。

## 2. 3つの採用メニュー
投稿メニュー：3 / 1 / 2 / 3
1. [相手募集] [募集+Room] [告知/予告]
2. [クリエーター有料ビデオ投稿]
3. [🔗ボタン作成] [検索/フィルター]
4. [雑談] [紹介/招待] [操作説明]

総合案内：2 × 6
1. [お知らせ] [フリートーク/雑談]
2. [全国エリアボード] [カテゴリーボード]
3. [ビデオチャット/動画] [検索/フィルター]
4. [みんなのプロフ] [コミュニティリンク]
5. [グループルール] [使い方]
6. [安全ガイド] [利用規約]

操作説明：3 × 2
1. [プロフ] [Room+募集] [告知/予告]
2. [🔗ボタン作成] [検索/フィルター] [戻る]

エリアブロック：地域案内に加え検索・フィルターの両方を設ける。雑談/戻るの配置も既決契約に従う。エリア固有の未確定ラベルを作らない。

## 3. プロフィール基本登録の確定UI
- 初回Bot DMに目的、作り方の①2行入力→②ポジション→③プレビュー、公開は別操作、再入力可、具体的な入力例を表示。
- 1行目はニックネーム、2行目は身長(cm)/体重(kg)/年齢(歳)。例：ゼロ ＋ 改行 ＋ 175 80 40。区切りは半角スペース、/、#、- を許容し3値の異常はエラー。
- 入力範囲は身長100～250cm、体重50～250kg、年齢18～89歳。17歳以下/90歳以上は入力不可。グループ参加条件も18歳以上であり旧20歳案は失効。
- ポジション1段目はタチ/タチリバ/リバの3ボタン、2段目はウケリバ/ウケ/S/Mの4ボタン、下にキャンセルして戻る。単一選択。2行テキストとポジション選択は前後どちらからでも可。エラー時に選択値を保持。
- プロフィールは非公開保存と公開を分離。キャンセルは未保存の今回の入力だけに適用。次のプロフィール②～⑤の未決定詳細は今後のロープレと決定を待つ。

## 4. モードを混同しない
- 作成中：共通プロフィール等を再利用し、選択・入力・部分修正から同じ枠のプレビューへ戻す。全項目の再入力を要求しない。
- 公開前：公開される本人情報・本文・投稿先を確認し、公開は明示操作の後。公開済み投稿の削除操作を公開前画面へ混ぜない。
- 公開後の本人専用マイ投稿：編集/コピー/転送用再生成/削除は本人限定。保存済み公開投稿のmessage_id等の同期は既決仕様に従い、一般的なウィザード画面掃除の対象にしない。
- 常設案内は既存公開メッセージIDへのリンク、検索・フィルターはBot DMの別操作。投稿管理と混在させない。

## 5. 開発・検証の完成条件
- 各ボタンの中身はMasterと逐次ロープレで確定し、確定範囲だけ実装する。未決定項目の推測追加/配置変更/勝手な公開接続は禁止。
- 確定した行配置・ラベル、ボタン内処理、画面ID維持、前後/取消、入力削除/失敗案内、値保持、競合/古いボタン拒否、DM/本人制御、非公開保存、公開資産の保護について毎セクション実装・テストを要する。
- 各メニューの配置が完成した段階で下位機能や公開接続が未完なのは当然。順次確定した後に接続・検証するので、現段階で配置が未完成という判定にはしない。
- Source/CIの合格とTelegram/iOS/Android実機合格を混同しない。Bot公開、PR merge、本番配備を実行したと装わない。
